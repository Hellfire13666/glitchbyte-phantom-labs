# 🌹⚡ GlitchByte Phantom Labs | LIVE OPSEC / OSINT Release Gate

**Effective for future new and explicitly upgraded network intelligence tools.** This is a mandatory engineering requirement, not a claim that all old builds already have working adapters.

## What counts as a real tool

1. **Live provider-backed requests:** The main/default research workflow contacts working public sources over HTTPS or an appropriate documented public protocol and processes **actual responses**. Public DNS, RDAP, certificate transparency, public web archives, provider APIs, and permitted public profile references are possible sources depending on the tool. Do not brand a local navigation page or a shell launcher as an intelligence engine.
2. **Streaming, useful findings:** Show colorful, readable status as work happens: selected domain/scope, each queried provider, elapsed time, counts, provenance, found observations, deduplicated totals, clear `RATE-LIMITED`, `TIMEOUT`, `PARTIAL`, `NO DATA`, `ERROR`, and `DONE`. Results may be empty. Never invent data, inflate counts, silently substitute synthetic records, or treat a 429/502 as a hit.
3. **Actual real-domain tutorials:** The tool page begins with at least **two genuine public-domain research runs** that use a real publicly resolvable domain such as `facebook.com`, or a domain the user controls. For each, verify the exact installed version and supported flags, document prerequisites and which live providers were tried, show honest observed output with a run date and source URLs, interpret uncertainty, and disclose failure/partial responses. Commands must be repeatable, but current results need not reproduce past values. A third Easy / Medium / Savage tier is added if the tool supports it. **No synthetic demonstration is the main Start button or flagship example.**
4. **Easy start and discoverability:** Provide a safe one-square install, a *separate* short Start command that works on repeat launches, optional menu/desktop shortcuts, real copy buttons, one clear tool homepage, and distinct `LIVE` / `OFFLINE TEST` labels. Add the home/recipes to Master Hub and its finder as appropriate; a page only opens documentation and never silently executes shell commands.
5. **Real integrated adapters:** Detect actual installed CLI versions and capability flags, invoke compatible installed HEXBAZAAR/RIFTSEAL or other adapters, and report incompatibilities visibly. An adapter that only checks for a file, returns canned JSON, or connects to obsolete file paths is **not** a verified live integration. Test one real end-to-end invocation on the owner's Linux version before marking a connection `LIVE VERIFIED`.
6. **Professional OPSEC by design:** Use only lawfully obtainable public data and consent/authorization for active target probes; respect provider rate limits and robots/service restrictions as applicable. Public source discovery does not justify bypassing login, harvesting secrets, probing private accounts, or claiming a real person's identity or misconduct from a match. Default to terminal-only/no persistent personal research reports where feasible; explicitly opt in to saved results, protect output using owner-only `0700` directories and `0600` files, strip tokens from logs, use bounded network timeouts and throttling, and document exactly what leaves the machine. Provide `--help`, Ctrl+C support, and honest error handling.

## Release acceptance evidence

- [ ] Real, reproducible domain query using the actual new or upgraded executable; save the command, date, version, provider status and **observed** output excerpts.
- [ ] At least two real-world copy/paste use cases (not synthetic samples) on that tool's webpage, README and Master Hub recipes.
- [ ] Every advertised live provider/adapter has a real invocation check; failing integrations are labeled `UNVERIFIED`, `PARTIAL` or `UNAVAILABLE`.
- [ ] Public-data output is source-attributed, rate-limited, deduplicated, honest about uncertainty, and does not expose tokens, credentials or private reports.
- [ ] One-square installer, short Start trigger, desktop/menu launch when relevant, and Easy / Medium / Savage commands all tested with the **actual supported options**.
- [ ] Review/test licenses, release contents and security boundaries; complete the [published Installer Vault backup](https://github.com/Hellfire13666/glitchbyte-phantom-labs-releases/blob/main/docs/INSTALLER_VAULT.md) before signing off a public release.

## Exceptions that must stay honest

Local-only utilities such as RIFTSEAL hashing, offline file forensics, artwork generators, and deterministic regression tests do **real work on local files** and must not pretend to access the internet. Such tools should use authentic local file examples and live feedback from their real workload. Network-backed research tools should have an offline *test mode* for development, but that mode must never be marketed as the primary live hunt.

The existing PHANTOM SPINE visual portal and Quickstart package are documentation/launcher releases, **not** proof its original live HEXBAZAAR adapters work with newer versions. PHANTOM SPINE may be marked `LIVE VERIFIED` only after testing its real end-to-end adapters. Likewise, a previous successful run on a given version does not prove future providers will stay available.

**Permanent motto: Real requests. Real provenance. Real feedback. Simple launch. Zero fabricated findings.**
