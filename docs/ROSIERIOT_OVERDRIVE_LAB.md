## 🌈 New-build documentation + distribution

Every RosieRiot component or companion upgrade follows the [Build → Run → Publish → Vault standard](BUILD_PUBLICATION_STANDARD.md): unique source and artwork, visible real findings/partial statuses, honest optional report behavior, tested [Simple/Medium/Extra instructions](BEGINNER_RUNTIME_RECIPES.md), and matching links from HQ, Cultivation, Tool Vault, the dedicated repository, and a verified backup. This is documentation policy, not a claim that every original module has already been rewritten.

## 🔧 Findomain workstation status

The [Findomain live-check and beginner recipe](integrations/FINDOMAIN_LIVE_CHECK.md) documents a successful 23-second public-source test on Ubuntu and the correct user-local installation path. Findomain remains an independently installed third-party option, not a claimed bundled module of the original RosieRiot engine.

**💾 Optional easy TXT output across future builds:** our [publishing standard](BUILD_PUBLICATION_STANDARD.md) now prefers `-o names.txt` when a project implements simple text export. [SUBDOMINATRIX already supports it](tool-showcases/SUBDOMINATRIX.md). The original RosieRiot engine still has its own documented report flags; this is not a universal option yet.

**💾 Save across lab tools:** [Easy Save for Every Tool](EASY_SAVE_ALL_TOOLS.md) defines `-o name.txt` and `--o name.txt` for future native tools and a [shared terminal transcript runner](../scripts/phantom_easy_save.py) for existing noninteractive CLI commands. The original RosieRiot engine's own saved-report behavior stays unchanged; do not assume it natively accepts those two flags.
