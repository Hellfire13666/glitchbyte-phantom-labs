Private Report Recipes

Save the public infrastructure output you choose, and protect private reports without making your home directory visible in the output.

✦ Start here⚡ Domain recipes⛓ Integration🔐 Evidence▤ Reports⌨ Linux shortcuts
FIRST TIME · LOCAL

Create the private report vault

Owner-only permissions for the reports you explicitly choose to save.
mkdir -p "$HOME/HEXBAZAARReports" && \
chmod 700 "$HOME/HEXBAZAARReports"
SAVAGE · LIVE

Save a fresh public-source JSON report

A timestamp prevents collisions. The tool refuses to overwrite an existing report.
cd "$HOME/PhantomLabsLaunchers/hexbazaar-savage-intel-shop-v0_1_2_rc1_rosie_facebook_recipes" &&
mkdir -p "$HOME/HEXBAZAARReports" && \
chmod 700 "$HOME/HEXBAZAARReports" && \
python3 -B hexbazaar_savage_intel_shop_v0_1_2_rc1.py \
  --color always \
  --out "$HOME/HEXBAZAARReports/facebook_public_$(date +%Y%m%d_%H%M%S).json" \
  domain facebook.com --live \
  --providers dns,ripe,certspotter,urlscan \
  --view full --limit 200 --timeout 4 --delay 1
EASY · LOCAL

See report filenames

Print the saved JSON filenames, not the contents. Only in the report vault.
ls -lh "$HOME/HEXBAZAARReports"
EASY · LOCAL

Check access permissions

Your report directory should be 700, and new JSON reports should be 600.
stat -c '%a %n' "$HOME/HEXBAZAARReports" "$HOME/HEXBAZAARReports"/*.json
Privacy: Reports can include public target names, discovered hostnames and evidence URLs. They are not appropriate for automatic GitHub uploads. The hub never reads report contents or indexes private JSON files.
